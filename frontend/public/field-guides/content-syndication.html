01

Before you start

Scans a client's site for existing content, lets you pick which pages to turn into unique rewritten versions, and publishes those as public, search-discoverable Google Docs and/or Sheets — each one linking back to the original. The live site is never touched.

nothing files itself

Scanning only discovers pages and lists them. Nothing goes out — not even on the first scan — until you personally select pages and hit Publish, every time.

A frozen client blocks publishing here too.

02

Turn it on & set preferences

  • "Auto-scan daily for new content" — the on/off switch; helper text shows the last scan date and reminds you it "never publishes on its own."
  • Content types to include — Blog posts / Pages / Products (all on by default). This only controls what a future scan adds — unchecking one after a type's already been discovered doesn't hide those existing rows.
  • "Publish to:" — Google Docs + Sheets / Docs only / Sheets only.
  • "Sharing:" — "Anyone can find & view (discoverable)" or "Anyone with the link can view."

Every setting saves immediately — no separate Save button.

03

Scan for content

Click Scan now anytime, or let the daily auto-scan handle it. A scan reads the sitemap (falling back to a live search-index lookup), sorts pages into blog post / page / product, and adds anything genuinely new as a discovered item. The "Scanning…" indicator near the title is a fixed ~45-second timer, not tied to the scan actually finishing — on a large site it can vanish before the job is really done; "Last scan" only updates once it truly completes.

04

Review & select

The items table shows title, type, and status, with filter tabs — All, Published, Not published, Failed — each labeled with a count. Tick a page (only selectable if not already fully published), or use Select all; the bulk bar shows a live count and where it's headed (e.g. "→ Google Doc + Sheet · public"). The table paginates at 50 rows.

05

Publish

Click Publish N. Each selected page is rewritten into a genuinely unique version and published as a Doc and/or Sheet per your settings, each with a backlink to the original.

Not publishedDiscovered, not yet published
Publishing…Being rewritten and pushed out right now
PublishedLive — Doc and/or Sheet chips link to it
FailedHover the red badge to see why

Re-selecting a page whose publish target you've since widened only fills the missing output — it won't duplicate what's already published.

06

Fixing failures

Any row marked Failed gets its own Retry button. Once you have published items, an "Export published CSV" button appears — title, source URL, type, Doc URL, Sheet URL, publish date.

Sheets need the Apps Script webhook redeployed — if you see sheet_not_supported, that's a one-time admin infra fix, not something a retry solves. Flag it.

07

Troubleshooting

Turned it on — did it publish my whole site?No. Only the daily scan is enabled; nothing publishes until you select pages and click Publish.
Can I un-publish something?Not from this tool — delete the Doc/Sheet directly in Google Drive.
Does this touch the original page?Never — it only reads the page to produce a copy elsewhere.
08

Practice exercises

  • Turn syndication on for a client and confirm nothing publishes on its own.
  • Run a manual scan and watch a new item appear in "Not published."
  • Select one page, publish it, and open the resulting Doc's backlink.
  • Widen publish_target on an already-published page and confirm it only fills the gap.
