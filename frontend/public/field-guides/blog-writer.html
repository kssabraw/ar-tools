01

Before you start

Two client-level settings shape every article this tool ever writes: Brand Voice and ICP. Set them on the client's own pages before you write anything real — every generator in the suite (Blog Writer, Local SEO, Ecommerce) reads the same record. Your own typed text always wins over whatever the app auto-generates; leave it unset and it still works, just less precisely.

stet — leave standing

The brief the pipeline builds is cached and client-agnostic — it gets reused across clients targeting the same keyword. The client-specific flavor (voice, ICP, page structure) only enters at the writing stage, not the brief.

5 runs at a timeOnly 5 generation jobs can be in flight across the whole suite. Bulk jobs and "reoptimize existing article" runs deliberately skip this cap — they don't count against it, they just queue and process sequentially in the background.
Frozen clientsPublish, Score, and Reoptimize all show a clear "This client is frozen" explanation when blocked. The New Run form is blunter — it just prints the raw client_frozen code — so check the red freeze banner on the client's workspace page first if something won't start.
Length limitsKeyword: 150 characters. Notes for the writer: 4,000 characters.
02

Start a run

Open the client → Runs → New Run.

  • Keyword — required, e.g. best hvac systems 2026.
  • Format — an optional override on the brief's own classifier: Auto (detect from keyword), Standard blog post, Listicle (ranked / "Best X"), How-to guide, Comparison (X vs Y), or Buying guide (commercial).
  • Notes for the writer — freeform guidance for stage 04 only (e.g. "mention Zero Down Supply Chain Services as one of the top 10 best"). It never enters the cached brief — it's a per-run instruction, not a permanent change to how that keyword gets briefed for anyone else.

When to override Format. Leave it on Auto for almost everything — the classifier reads the keyword well. Override it when the keyword is genuinely ambiguous ("best hvac systems" could read as a listicle or a buying guide) and you already know which one the client wants, or when a past run on this keyword picked the wrong shape and you're re-running specifically to fix that.

Click Start. If a cached brief already exists for that exact keyword, a dialog asks whether to reuse it (faster, cheaper) or force a fresh one — worth forcing if the SERP landscape has genuinely shifted since it was last researched.

04

When a stage fails

An amber box reading "Auto-retry" means exactly that — it's automatically retrying a transient upstream error, not broken. Leave it. A genuine failure shows "Failed at the <stage> stage" plus an expandable error accordion ("What to do" / "Hide") — a plain-English explanation, numbered fix steps, and, when there is one, a one-click fix button.

From there you get three buttons, and they are not interchangeable:

ResumePicks up from the last completed stage, reusing everything already done. Try this first — it's the cheapest.
RestartFailed/cancelled runs only. Spawns a brand-new run with the same client and keyword, and defaults to regenerating the brief and SIE from scratch (you still get the usual cache-decision dialog first).
RerunComplete runs only. Same as Restart — a new run, cache regenerated by default — for when you want a genuinely fresh pass at a keyword you already published.
05

Review the article

Once complete, you'll see:

  • QA Checks — a green "All QA checks passed" line, or an amber list flagging a format mismatch, an unhonored writer note, thin entity coverage, keyword-stuffing, or a low-confidence intent read.
  • Title & H1 — the SEO/meta title and the on-page H1, separately copyable (they're often intentionally different).
  • Generated Article — Markdown/HTML toggle, Copy, Download, and a Featured image picker.
  • Term Usage by Zone — which related keywords/entities landed in the title, H1, subheadings, and body, without re-reading the whole thing.
06

Publish — and the voice gate

A run has to be Complete before any publish button works. Three destinations, each its own button on the article card:

  • Publish to Google Docs — drops into the client's Drive folder; the button becomes "Open Doc" on success.
  • Publish to WP — pick Draft or Publish from the dropdown first.
  • Publish to GitHub — commits the markdown; if hero/body-image generation is configured for the client it runs as a background job ("Generating images…"), otherwise it commits synchronously with no images at all.

Which destination to pick. Google Docs is the default for a client who reviews before anything goes live — it lands as a draft doc, not a publish, so it's the safe choice when you're not sure. WP (WordPress) is for a client whose site the suite can publish to directly: choose Draft if a human still needs to hit publish on their end, or Publish only for a client you already trust the pipeline's output for — it goes live immediately. GitHub is for a client with a suite-built website (the Website Builder module) — that site's repo is its actual source of truth, so this is the only destination that's "publishing" in the sense of shipping to the real site, not a review copy.

approved on hold — voice

If the article used a word from the client's "never use" list, publish is blocked — a hard, provable gate. A low voice score alone never blocks; only a forbidden word does. Fix the wording and regenerate, or, if you're confident it's fine, click Publish anyway — a deliberate, one-extra-click override.

no stet on this one

Regulated clients (dosing, branded-drug claims, guaranteed-results language) carry a separate compliance gate that is not overridable from the UI. That one needs an actual rewrite — there's no stamp that gets around it.

07

Score & reoptimize

An article you already generated

On any complete run, the Article score card checks it against the blog/AEO rubric — Organic Ranking, AEO/LLM Retrieval, Content Depth, Entity & Topic Coverage, E-E-A-T & Citations, ICP Alignment, Structural AEO, SERP Signal Coverage. Click Score (becomes Re-score after the first pass). Deficiencies surface as checkboxes — tick the ones to fix (or leave none ticked to fix everything) and click Reoptimize; it rewrites against exactly those issues, then re-scores automatically, in the background. Both panels also carry an Entity engine selector (TextRazor by default, or Google NLP).

Which entity engine. Leave it on TextRazor — it's the default for a reason and usually the better read. Switch to Google NLP mainly to cross-check a borderline entity-coverage score, or when the topic is technical/niche enough that Google's model might have better coverage of the specific entities involved.

A URL that isn't a suite run

From the Runs page (not inside a specific run), two toggles: Score an article — point at a live URL or paste content, plus a required keyword; scores only, rewrites nothing. Reoptimize an article — same inputs, plus optional notes, accepts either one URL or a pasted list of several. Unlike scoring, this spawns a genuine new run — full brief → research → writer — since there's no existing brief to reuse.

Score first, reoptimize second. Score is the cheap move — run it on a competitor's page or a not-yet-suite page just to see where it stands. Only spend on Reoptimize once the score actually tells you it's worth a full rewrite; on a URL that isn't a suite run, that rewrite is a genuine new pipeline pass, not a cheap patch.

08

Content Silos

As briefs get generated, the suite quietly groups related keywords into content silos — topic clusters it noticed recurring across your briefs, no tagging required. Check the Silos page in the sidebar periodically: a banner flags topics worth a real look, and each row has icon buttons to Approve, Reject, or approve-and-immediately-dispatch a run. The bulk toolbar mirrors the same three actions as buttons: Approve & generate, Approve only, Reject.

Approve only vs. Approve & generate. Approve only when you want the topic on record for later — building out a content calendar without committing spend yet. Approve & generate when you're ready to write it now. Reject a grouping that's genuinely a bad fit (unrelated keywords lumped together by coincidence) rather than leaving it sitting in the list for someone else to puzzle over.

10

Troubleshooting

Stuck on "Retrying"Not a failure — an automatic retry on a transient upstream error. Leave it; it'll either succeed or eventually surface a real failure with the error accordion.
Can I edit the article by hand?The generated content publishes as-is. Steer it with the Notes field on the next run, or Score → Reoptimize, rather than hand-editing in the dashboard.
Reoptimize spawned a new run instead of editing this oneOnly happens from the "Reoptimize an article" path for content that isn't already a suite run — there's no brief/research to reuse. Reoptimizing a run you already generated rewrites in place and is much cheaper.
Hit the 5-run capWait a minute for something in flight to finish. A big bulk batch running elsewhere doesn't block you outright — a smaller ad-hoc run just queues briefly behind it.
Voice or ICP not showing up in the writingCheck the client's Brand Voice and ICP pages — unset, the suite auto-generates a reasonable default from the site/GBP, which isn't the same as your own guidance.
11

Practice exercises

  • Start a run on a client with no cached brief for the keyword, and watch all five stages complete without touching the page.
  • Deliberately trigger the cache-decision dialog by re-running a keyword you've already briefed — choose reuse, then try again and choose regenerate.
  • Publish a completed run to Google Docs, then confirm the button flips to "Open Doc."
  • Score a complete run, tick exactly one deficiency, and Reoptimize — compare the before/after score.
  • Find a keyword's Content Silo (if one exists yet) and Approve it from the Silos page.
